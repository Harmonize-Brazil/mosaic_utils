
Usage
=====

The command-line utility ``crop-mosaic`` automatically removes unstable
border regions from orthomosaics generated by UAV photogrammetry.

The resulting cropped mosaic preserves all raster bands, georeferencing
information and metadata while removing invalid border pixels commonly
found around the reconstructed area.

Basic Usage
-----------

Crop a mosaic using the default parameters:

.. code-block:: shell

    crop-mosaic \
        --mosaic_image path/to/mosaic.tif \
        --threshold_area 0.005

The output raster is automatically written as:

.. code-block:: text

    path/to/mosaic_cropped.tif


Examples
--------

RGB Orthomosaic
~~~~~~~~~~~~~~~

For RGB orthomosaics generated by most photogrammetry software, the
validity mask is automatically obtained from the alpha band.

.. code-block:: shell

    crop-mosaic \
        --mosaic_image rgb_mosaic.tif \
        --threshold_area 0.005

Output:

.. code-block:: text

    rgb_mosaic_cropped.tif


Multispectral Orthomosaic
~~~~~~~~~~~~~~~~~~~~~~~~~

Multispectral orthomosaics commonly include an alpha band that defines
the valid image footprint. No additional parameters are required.

.. code-block:: shell

    crop-mosaic \
        --mosaic_image multispectral_mosaic.tif \
        --threshold_area 0.005

Output:

.. code-block:: text

    multispectral_mosaic_cropped.tif


Thermal Orthomosaic
~~~~~~~~~~~~~~~~~~~

Thermal orthomosaics may be handled in different ways depending on how
they were generated.

Many products contain a GDAL dataset mask or a zero-valued background,
allowing the validity mask to be determined automatically.

When automatic detection is not possible, a user-defined threshold may
be supplied:

.. code-block:: shell

    crop-mosaic \
        --mosaic_image thermal.tif \
        --mask_band 1 \
        --mask_threshold 15 \
        --threshold_area 0.005

Output:

.. code-block:: text

    thermal_mosaic_cropped.tif




How the Validity Mask is Determined
-----------------------------------

Before cropping, ``crop-mosaic`` derives a binary validity mask that
defines the mapped area. The mask is determined automatically using the
following priority:

1. **Alpha band** (recommended for RGB and multispectral orthomosaics).
2. **GDAL dataset mask**, when available.
3. **Automatic background detection**, when the background value can be
   inferred (typically zero-valued pixels surrounding the mosaic).
4. **User-defined threshold**, specified with ``--mask_threshold``.

In most cases no additional parameters are required. During processing,
the program reports which method was selected.

User-defined Threshold
~~~~~~~~~~~~~~~~~~~~~~

The option ``--mask_threshold`` can be used when the validity mask
cannot be determined automatically.

The threshold is applied to the band specified by ``--mask_band``.
Pixels with values **greater than or equal to** the threshold are
considered valid, while values below the threshold are treated as
background.

For example:

.. code-block:: shell

    crop-mosaic \
        --mosaic_image thermal.tif \
        --mask_band 1 \
        --mask_threshold 15\
        --threshold_area 0.005

In this example, every pixel whose value is **greater than or equal to
15** is considered part of the mapped area.

.. note::

   Depending on the software used to generate the orthomosaic, different
   strategies may be selected automatically:

   * RGB and multispectral mosaics usually contain an **alpha band**.
   * Some thermal mosaics include a **GDAL dataset mask**, which is detected
     automatically.
   * Other thermal mosaics have a constant background (typically zero),
     allowing the validity mask to be inferred automatically.
   * Only when none of these strategies succeeds is it necessary to
     provide ``--mask_threshold`` explicitly.



Command-Line Help
-----------------

Display the complete list of available options:

.. code-block:: shell

    crop-mosaic --help


Typical Workflow
----------------

A typical workflow consists of:

1. Generate the orthomosaic using your preferred photogrammetry software.
2. Execute ``crop-mosaic``.
3. Use the resulting cropped mosaic in subsequent GIS or remote sensing
   analyses.

The processing pipeline used internally by the algorithm is described in
:doc:`crop_mosaic`.
